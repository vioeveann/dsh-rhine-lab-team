# 发布与安装

## 包内容

```
index.js            Host 半区加载器
host/*.js           路由、工具、设置、模板、记忆
client.js           Client 半区（单个 classic 脚本）
templates/          团队模板（研究组 / 写作组）
docs/               设计说明、运行时笔记、本文件
locale/             详情页文案
LICENSE             MIT
```

自带成员（审计员 / 资料整理 / 写作）由 `host/builtin-bots.js` 在首次启动时种下，不随包附带 `bots/`；个人成员、测试 Bot、记忆和头像都不进包。

## 发布前检查

先确认 npm 上 `dsh-avatar-frame` 的 `latest` 已经是 `0.15.0` 或更高：本插件把依赖声明为 `latest`，安装/更新时会拉最新版；如果 npm 上还没有 0.15.0，装到的会是旧版，子会话头像与 ID 不完整。发布顺序是先发头像插件，再发本插件。

```sh
git status                       # 应该干净，没有漏提交的改动
node --test test/*.test.mjs      # 全部测试
node --check client.js index.js  # 语法
node --check host/*.js
npm pack --dry-run               # 看会打进去哪些文件
```

## 安装

```sh
dsh plugin add <包名或本地路径>
```

装好后：

1. 在插件列表里**启用 dsh-team**（bundle 需要单独启用一次）；
2. 可选：同时启用 `dsh-avatar-frame` ≥ 0.15，子会话才会显示 Bot 自己的头像和名字；
3. 新开会话，在**新会话页**或输入框下方打开「团队协作」开关；
4. 右侧栏出现「成员」面板，点 `＋` 建第一个 Bot，或点「套用模板」用现成的一套。

## 版本

- `0.7.4`（当前）：修 0.7.2 引入的 detach 异步派活「干完不叫醒秘书」。后台接力拿到结果后走 `subagents.sendMessage` 补一条消息，但 DSH 只允许「活着的调用者」调它——定时器回调不属于任何一轮，调用被拒并只留一条 debug（`subagent tree access requires the exact live caller`），账本照写 `ready`、主会话却毫无动静，只能靠人自己发现。现在 `notifyParent` 先照旧试 `sendMessage`，被拒就用 `sessionController.prompt` 把同一句话直接投进秘书会话（与私聊喊人同一条路），`detached-notify` 的 debug 行加 `via` 字段标明走的哪条路。不改 DSH 本体。
- `0.7.3`：修两处会话工作区与开关问题。① 审计等已完成任务的会话不再被当成普通会话——`botChatOf` 对任何绑定了 Bot 的任务行都返回工作聊天，客户端不再缓存空结果，Bot 会话里的「团队协作」开关稳定隐藏。② 私聊 Bot 里点「新会话」时，若当前工作区是「私聊会话」，自动改回私聊工作区之前的工作区，避免新会话落进私聊目录；只包插件客户端，不改 DSH 本体。
- `0.7.2`：`team_dispatch` / `continueFrom` 新增 `detach` 异步派活——调用立刻返回 `status: running` 和任务号，不把主会话占在等待里；Bot 完成或超时会通过团队消息唤醒主会话，并照常自动建审计。只支持单件，`team_dispatch_many` 批量仍同步汇总。另把后台接力的超时也改成会给主会话补一条消息，不再只广播；无文字产出的回合按 `turn/end` 收尾，不再空等最后一句。
- `0.7.1`：删掉 Bot 时把它那条私聊会话一并归档（记录保留、从左侧列表收起），并清掉 `private.json` 条目；插件启动时也扫一遍，清理「Bot 早删了、会话还挂着」的遗留。删掉的 Bot 再点头像返回「这个 Bot 已经不在了」；万一从归档里翻出它的旧会话，也不再被当成秘书会话，只回一句实话。
- `0.7.0`：私聊从子代理改成**独立根会话**——不再挂 ANY 主会话下面，所以主会话里不会再飘进「子代理完成」的通知；私聊会话出现在左侧列表（独立「私聊会话」工作区，排在最后），点开时归档过的会另开一条（旧的标成「名字（存档 月-日）」）；Bot 会话里隐藏「团队协作」开关、协调类工具一律收起来；私聊里只剩一个 `remember`，其余工具在执行口拦掉（guard）。
- `0.6.0`：改人设不用新开会话（人设段的 text 用取值函数，每次组装现取）；工作聊天按主会话隔离，一个主会话一条；私聊独立记录、跨主会话复用（0.6.0 时还是子代理，0.7.0 改成根会话）；点头像进私聊、未读红点。
- `0.5.6`：修单聊在根会话失效后发不出去。DSH 要求子会话的根会话在线，旧实现把单聊挂在当时的会话下，重启后根已停止，`sendMessage` 返回 `subagent/delivery-unavailable`。现在客户端一律走 `/dsh-team/open`：服务端先判断原单聊的根是否活着，活着复用，死了在当前会话新开一条；账本同时记 `parentSession` 与 `rootSession`。另补进程级路由撤单，避免热重载时 `identity-map` / `session-bot` 重复注册。
- `0.5.5`：修两处状态错位。①「待命」误判：成员卡原先只认账本里的 `running` 行，派活那次工具调用一旦被打断（用户在派活途中插话），账本被记成 `ready`，子会话却还在后台跑——面板显示「待命」、看门狗关机、干完也没有任何回报。现在成员繁忙状态同时看会话实际运行态（新增 `host/live-watch.js` 订阅子会话 `agent/status`）；派活被打断时不再收 `ready`，任务保留 `running` 并标 `detached`，由后台接力每 3 秒查子会话是否真说完，拿到答复再收尾并广播 `task-done`。②热重载后新子会话头像回落主会话：`team-mode.js` 的 `dispose()` 漏撤 `identity-map` 与 `session-bot` 两条 exact 路由，重载时新实例撞 `duplicate exact route` 注册失败，`/dsh-team/identity-map` 一直由已卸载的旧实例供数、数据冻结在重载那一刻。现已补进撤单清单；客户端身份映射改为并行拉 `tasks`/`roster` 现拼，不再单依赖 `identity-map`。另：`host/runtime.js` 的 `tools.js`/`team-mode.js` 改成带版本参数的动态 import，翻开关即可热加载。
